## แผน

### เฟส 0 (1–2 สัปดาห์) — พิสูจน์ว่าปัญหามีจริง

- เขียน generator ของ pointer-chase (ปรับความยาวโซ่ได้)
- ยิงเข้า Qwen-VL / LLaVA ที่มีอยู่ **ไม่ต้องเทรนอะไรเลย**
- วัด accuracy เทียบกับความยาวโซ่ + **blind baseline** (ลบภาพทิ้ง)
- **วัด shortcut ตรงๆ ด้วย** — hook attention weight ที่ตำแหน่งคำตอบ ดูว่ามวลตกบน visual token เท่าไหร่ เทียบกับตกบน latent/reasoning token เท่าไหร่ (โค้ดประมาณ 20 บรรทัด) — อันนี้คือการวัด $\beta$ ด้วยมือตัวเอง แทนที่จะอ้าง paper อย่างเดียว

> **Kill criterion**: ถ้า SOTA ทำโซ่ยาว 4 ได้สบาย → ปัญหาไม่มีจริง → **หยุด**

**เฟสนี้อย่างเดียวก็คุยกับอาจารย์ได้แล้ว** ถ้ามันตกที่โซ่ยาว 2 จริง = มีกราฟที่ทรงพลังในมือ และเป็นกราฟที่**ไม่ขึ้นกับว่าโมเดลผมจะเวิร์คมั้ยเลย**

### เฟส 1 (~1 เดือน) — โมเดลเล็กที่สุดที่เป็นไปได้

- glance ภาพย่อ 64×64 → เลือก $(l_t, s_t)$ → trilinear read จาก pyramid → วน
- latent = **เวกเตอร์ตัวเดียว**, $T$ glimpse, **ไม่มี LLM ไม่มี pretrain**
- baseline: ViT เต็มภาพ / glimpse สุ่ม / **ขนาน-$k$ (สำคัญที่สุด)**
- แล้วค่อยรัน ablation 4 arm ข้างบน (A/B/C/D) ที่งบการอ่านเท่ากัน

> **Kill criterion**: ถ้า sequential ไม่ชนะ parallel → ไม่มี reasoning เกิดขึ้น → **กลับไปแก้ dataset ไม่ใช่แก้โมเดล**

### เฟส 1.5 — เอา Hopfield มาแทนการเดาจุดถัดไป (ดูหัวข้อล่าง)

พอเฟส 1 มีตัวรันได้แล้ว ค่อยเปลี่ยนวิธีเลือกจุดถัดไปจาก MLP ธรรมดา เป็น associative retrieval แล้วเทียบกันตรงๆ — เพราะมันเป็นการเปลี่ยนตัวแปรเดียวอีกเหมือนกัน

### เฟส 2 (ถ้าเฟส 1 รอด)

แปะเข้า VLM จริง / adaptive halting / ทดสอบบน V\*Bench, HR-Bench
**อย่าเริ่มที่นี่เด็ดขาด** — พังแล้ว debug ไม่ได้ว่าพังเพราะอะไร

## สิ่งที่ต้องยอมรับก่อนโดนถาม

| ประเด็นที่จะโดนถาม                                                  | ท่าที                                                                                                                                                                                |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| "มีคนทำ visual search ที่ zoom ได้แล้วนะ (V\*/SEAL, ZoomEye, DyFo)" | **จริง และบางอันไม่ต้องเทรนด้วยซ้ำ** ต่างกันตรง**ของเขา zoom ผ่าน tool call / crop ที่สื่อสารด้วยภาษา ของเราคือ latent ปล่อยพิกัดออกมาเอง และ differentiable ทั้งวง**                |
| "CapImagine ที่ใช้ text imagination ชนะ latent ไปแล้ว"              | **ยอมรับ** — มันชนะเพราะมัน _ตรวจสอบได้และ grounded_ ไม่ใช่เพราะมันเป็น text → **พิกัดคือ symbolic interface ที่เล็กที่สุด**: 2 ตัวเลข เทียบกับ ~200 token ตรวจสอบได้เท่ากัน ราคา 1% |
| "efficiency อย่างเดียวขายไม่ได้"                                    | **จริง** → ขายคู่กับ **interpretability** ($l_t, s_t$ พล็อตทับภาพได้ตรงๆ) และขายว่าเป็น **test-time compute สำหรับภาพ**                                                              |
| "recurrent visual attention ตายไปแล้ว"                              | ตายเพราะ **parallelism + โจทย์ไม่บังคับให้เป็นลำดับ** ไม่ใช่เพราะ REINFORCE — เงื่อนไขทั้งสองข้อเปลี่ยนไปแล้ว                                                                        |
| "ทำไมไม่ใช้ pretrain VLM เลย"                                       | เฟส 2 ค่อยทำ ถ้าเริ่มที่นั่น **แยกไม่ออกว่าอะไรพัง**                                                                                                                                 |
| "ถ้า benchmark ไม่ deep-hard จะพิสูจน์ไม่ได้"                       | **ใช่ นี่คือเหตุผลที่เฟส 0 ต้องมาก่อน**                                                                                                                                              |

### คำถามที่ควรถามอาจารย์ (สำคัญกว่าสิ่งที่จะเล่า)

1. มี dataset ที่บังคับ referential chain อยู่แล้วมั้ย หรือต้องสร้างเอง
2. สร้าง synthetic benchmark เองแล้วตีพิมพ์ได้ระดับไหน (workshop / dataset track / main)
3. มี compute ให้เล่นแค่ไหน — จะได้ scope ให้พอดี
4. มีใครในแล็บทำสาย interpretability มั้ย

### วิธีเปิดเรื่อง — เปิดด้วยข้อสังเกต ไม่ใช่ไอเดีย

> _"ผมสังเกตว่า latent reasoning เวิร์คใน text แต่มีงานที่พิสูจน์ด้วย causal mediation ว่าไม่เวิร์คในภาพ — latent token ทำตัวเป็น placeholder_
>
> _ผมคิดว่าสาเหตุไม่ได้อยู่ที่โมเดล แต่อยู่ที่โจทย์ — vision benchmark สืบทอดจากยุค CNN ที่ยากแบบกว้าง ไม่ใช่ยากแบบลึก โมเดลเลยไม่มีเหตุผลจะคิดเป็นลำดับ_
>
> _ผมอยากทดสอบสมมติฐานนี้ด้วยงานที่บังคับให้ลึก แล้วดูว่ากลไกแบบ recurrent visual attention กลับมามีความหมายมั้ย"_

พอมีข้อสังเกตนำหน้า ไอเดียจะฟังเหมือน**ผลของการคิด** ไม่ใช่ของที่หยิบมามั่ว

## เช็คแล้ว — ตรงไหนของร่างเดิมที่ต้องแก้

ไล่เช็คทุก claim ในร่างแรกแล้ว เจอ 6 จุด แก้ในเนื้อให้แล้ว บันทึกไว้ว่าแก้อะไรบ้าง

| #   | ร่างเดิมเขียนว่า                                                                    | สถานะ                              | ที่ถูกคือ                                                                                                                                                                                                                                                                                                                                                           |
| --- | ----------------------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | RAM ทำให้ "โมเดลมองภาพได้แคบและจำกัด" จนต้องไปแก้ที่ตัวภาพ (ยกตัวอย่างตาซ้าย-ตาขวา) | **แก้แล้ว — ให้เครดิต RAM น้อยไป** | RAM **มี** peripheral vision อยู่แล้ว (วงนอกที่หยาบแต่กว้าง) ตัวอย่างตาซ้าย-ขวาเลยแก้ได้ด้วยวงนอก **ข้อจำกัดจริงคือความกว้างของวงนอกมันคงที่ คนตั้งครั้งเดียวใช้ทั้ง dataset** — ซึ่งเป็นข้อโต้แย้งที่**แข็งกว่าเดิม** เพราะมันชี้ตรงไปที่ learned scale พอดี                                                                                                       |
| 2   | ViT "มี inductive bias ต่ำ ทำให้ต้องใช้ข้อมูลมหาศาล"                                | **⚠ ต้องระวังตอนพูด**              | จริงในสูตรปี 2020 เท่านั้น — **DeiT / AugReg / MAE / DeiT-III ทำได้ 83–85% บน ImageNet-1k ล้วนๆ** และ DeiT-III แสดงว่า gap ปี 2020 ส่วนใหญ่เป็น **recipe artifact** ถ้าพูดว่า "ViT ต้องใช้ JFT-300M" อาจารย์ที่ตามสายนี้สวนได้ทันที ที่ยังจริงคือ: prior ที่หายไปต้องจ่ายด้วยอะไรสักอย่าง (data / augmentation / distillation / conv stem) และทุกวิธีได้กำไรพอๆ กัน |
| 3   | ViT ลดขนาดของ "cross attention"                                                     | **แก้แล้ว — คำผิด**                | ViT ใช้ **self**-attention ($O(N^2)$) ส่วน cross-attention เป็นของ Perceiver ($O(MN)$) — คนละตัว                                                                                                                                                                                                                                                                    |
| 4   | Perceiver IO "มองภาพได้ทีเดียวเท่านั้น"                                             | **แก้แล้ว — ไม่จริง**              | Perceiver ตัวแรก **วนอ่านหลายรอบ** (weight sharing) ส่วน IO ลดเหลือ ~รอบเดียวเพราะ output query ดึงรายละเอียดตรงจาก input ได้ **คำวิจารณ์ที่ถูกไม่ใช่ "อ่านได้ครั้งเดียว" แต่คือ "ทุกครั้งที่อ่าน ราคาเท่ากันและอ่านทั้งภาพ — ไม่มีการอ่านแบบถูกให้เลือก"** ซึ่งตรงกับ thesis เรามากกว่าด้วย                                                                        |
| 5   | ตัวอย่าง "ทำนายคำต่อไปของ 1 2 3 4 5" ว่าเป็นการคิดเชิงลึก                           | **แก้แล้ว — ตัวอย่างอ่อน**         | อันนั้นเป็นงานทรง **induction head** = วงจร 2 layer ตื้นๆ ยกไปแล้วโดนสวน เปลี่ยนเป็น **GSM8K** (5 ขั้น ไม่มีทางลัด) และเหตุผลจริงที่ภาษาเป็น latent โดยธรรมชาติคือ **มันเป็น sequential เชิงโครงสร้าง + มี supervision รายขั้นฟรีจากข้อความที่มนุษย์เขียน** ไม่ใช่เพราะ $z$ แต่ละตัวลึกขึ้นเรื่อยๆ                                                                  |
| 6   | "เป็นการเปลี่ยนวิธีแก้ปัญหา แต่เป็นการเปลี่ยนตัวปัญหา"                              | **แก้แล้ว — ตกคำว่า "ไม่ใช่"**     | "**ไม่ใช่**การเปลี่ยนวิธีแก้ปัญหา แต่เป็นการเปลี่ยนตัวปัญหา"                                                                                                                                                                                                                                                                                                        |
| 7   | Deformable DETR = "คงที่"                                                           | **แก้แล้ว — แรงไป**                | มันเรียน sampling offset ต่อ query **และ** เรียนน้ำหนักข้าม feature level ที่ถูกคือ **เซ็ตของสเกลตายตัวและไม่ต่อเนื่อง โมเดลเลือกจากเมนู ไม่ได้ปล่อยค่าสเกลออกมาเอง**                                                                                                                                                                                               |
| 8   | ใช้ตัวแปร $k$ แทนสเกล                                                               | **แก้แล้ว — ชนกัน**                | เปลี่ยนเป็น $s$ เพราะ $k$ ชนกับ "จำนวนวง retina" ของ RAM และ "ความยาวโซ่" ของ pointer-chase                                                                                                                                                                                                                                                                         |

### 🔴 อันนี้สำคัญกว่าทุกข้อข้างบน — ต้องทำก่อนเจออาจารย์

**paper ที่เป็นฐานของ argument ทั้งหมด (Li et al., ICML 2026 — causal mediation ที่พิสูจน์ว่า latent visual token เป็น placeholder) ยังไม่ได้อ่านต้นฉบับ** ตอนนี้มันมาจากการเสิร์ชอย่างเดียว (โน้ตในคลังเตือนเรื่องนี้ไว้ 3 ที่แยกกัน ว่า paper ปี 2026 ทั้งหมดในคลังยังไม่ได้อ่านต้นฉบับ)

ถ้าเปิดเรื่องกับอาจารย์ด้วย paper นี้แล้วรายละเอียดไม่ตรง มันพังทั้ง argument — **อ่านให้จบก่อน** และเช็คว่า:

- $\alpha, \beta$ ที่เขาวัด นิยามยังไงแน่
- เขาทดสอบกับ latent method ตัวไหนบ้าง
- เขา*ไม่ได้*เคลมอะไร (เผื่อเราไปเคลมเกินให้เขา)

ตัวที่ควรอ่านคู่กันอีก 2 อัน: **CapImagine** (คู่แข่งตรงที่สุด — text imagination ที่ชนะ latent) และ **Attention Sampling** (สั้น ตอบคำถามเรื่องต้นทุนการอ่านเยอะ)

### สิ่งที่เติมเข้าไปใหม่ (ไม่ได้อยู่ในร่างเดิม)

- **§ทำไมผมถึงเลือกทำอันนี้ก่อน** ทั้งหัวข้อ — โดยเฉพาะข้อ 1 (ลบ path B ได้จริง) กับข้อ 2 ($I(z;y \mid \text{glance}) > 0$) เพราะร่างเดิม**อธิบายปัญหา shortcut ไว้ แล้วก็อธิบายไอเดีย $(l,s)$ ไว้ แต่ไม่เคยเชื่อมสองอันเข้าหากันเลย** ว่าทำไม $(l,s)$ ถึงแก้ shortcut ได้ — ซึ่งมันคือหัวใจของคำถามที่ว่า decision มาจากไหน
- **ตารางเดียวที่รวมสามระบบเป็นความล้มเหลวเดียวกัน** (ใครตัดสินว่าอ่านอะไร / อ่านกี่ครั้ง / ราคาต่อครั้ง) — ร่างเดิมบ่นสามเรื่องแยกกัน พอรวมเป็นตารางเดียวแล้วไอเดียนี้กลายเป็นก้าวถัดไปที่ชัดเจน ไม่ใช่ของที่หยิบมามั่ว
- **aliasing / pyramid** — ร่างเดิมไม่มีเลย และมันคือส่วนที่ตัดสินว่าไอเดียรอดหรือตาย
- **การทดลอง 4 arm (A/B/C/D)** — เพราะ contribution จริงคือตัวแปรเดียว ต้องมี arm ที่ต่างกันแค่นั้น ไม่งั้นแปลผลไม่ได้
- **เหตุผลว่าทำไม RAM ตายจริงๆ** — เป็นคำตอบของคำถามแรกที่อาจารย์จะถาม และร่างเดิมไม่มี
- **เรื่องไม่มีโจทย์ + pointer chase + เฟส 0** — ร่างเดิมไม่มีแผนเลย
- **หัวข้อ Hopfield retina** ต่อท้าย
