# เป้าหมาย ปัจจุบัน -> **Bounded-bandwidth visual reasoning**

---

## ปัญหา

ลองไล่ดูว่าปัจจุบันเราให้โมเดล "อ่าน" ภาพยังไงบ้าง

**RAM (2014)** — retina มีหลายวง (`k` วง) กลางเดียวกัน วงนอกกว้างกว่าเป็นเท่าตัว แล้วย่อทุกวงลงมาเป็น $g \times g$ เท่ากันหมด โมเดลเรียนได้แค่ว่าจะวางจุดกลางตรงไหน (`l`) ส่วน**จะมีกี่วง วงกว้างแค่ไหน คนตั้งให้หมด** ตั้งครั้งเดียวใช้ทั้ง dataset

เรื่อง "วงนอก" นี่สำคัญ เพราะมันคือ peripheral vision — มันคือคำตอบของปัญหาที่ว่าโมเดลจะรู้ได้ยังไงว่ามีของอยู่ตรงที่ยังไม่ได้มอง (เช่นกำลังดูตาข้างขวา จะรู้ได้ไงว่ามีตาข้างซ้าย ถ้าไม่เคยมองไปตรงนั้น) RAM แก้ด้วยวงนอกที่หยาบแต่กว้าง

**แต่ปัญหาคือความกว้างของวงนอกมันคงที่** ถ้าภาพหน้าใหญ่เต็มเฟรม วงนอกอาจจะพอ ถ้าหน้าเล็กอยู่มุมนึงของภาพ 2000×2000 วงนอกไม่เห็นอะไรเลย — และโมเดลปรับเองไม่ได้ ต้องกลับไปแก้ที่ preprocessing หรือไปแก้ที่ตัวภาพเอา

มีวิธีอื่นที่คนใช้กันในการแก้ปัญหา "จะรู้ได้ไงว่าต้องไปไหนต่อ" อยู่ 4 ทาง: peripheral vision (RAM) / เดาจากภาพเต็มทีเดียว (amortized regression) / เบลอก่อนแล้วค่อยชัด (coarse-to-fine) / สุ่ม — **สังเกตว่าไม่มีอันไหนแก้ด้วยการไล่ gradient บน $l$ ตรงๆ เลย** เพราะ gradient ของตำแหน่งมันรู้แค่ texture ตรงที่มองอยู่ ต่อให้ทำ kernel กว้างขึ้น (box → bilinear → Gaussian) ระยะเอื้อมมันโตแบบกำลังสอง สุดท้ายเอื้อมได้ทั้งภาพก็แพงกว่าอ่านทั้งภาพไปเลย

**ViT (2020)** — เราตั้ง patch size เอง เพื่อกด $N$ ลงมาให้ self-attention จ่ายไหว (attention เป็น $O(N^2 D)$ ถ้าอ่านทีละ pixel ที่ 224×224 มันแพงกว่า patch 16×16 อยู่ 65,536 เท่า)

ที่เสียไปไม่ใช่ "ข้อมูล" นะ — ViT-B/32 บีบ $32^2 \times 3 = 3072$ ลงเหลือ 768 มิติ คือ lossy ชัดๆ แต่ก็ยังทำงานได้ดี **สิ่งที่เสียไปคือ prior** คือความรู้ฟรีๆ ที่ CNN มีมาแต่เกิดว่าพิกเซลใกล้กันเกี่ยวข้องกัน attention มัน _เขียนแทน convolution ได้_ (Cordonnier 2020 พิสูจน์ไว้ ถ้ามี relative PE และหัวพอ) แต่ **SGD ต้องไปหาเจอเอง** — เขียนได้ ไม่ได้แปลว่าหาเจอ

**Perceiver / Perceiver IO (2021)** — ยัด long sequence เข้าไปตรงๆ ให้ latent $M$ ตัวไป cross-attend กับ input $N$ ตัว ราคา $O(M N d)$ ไม่ใช่ $O(N^2 d)$ ซึ่งถูกลงมาก

แต่ **การอ่านครั้งเดียวของมันแพงมหาศาล** — cross-attend หนึ่งครั้งของ Perceiver ≈ self-attention block 22 อัน คิดเป็นประมาณ **80% ของ compute ทั้งโมเดลคือค่าอ่าน ไม่ใช่ค่าคิด** และที่สำคัญกว่าคือ **ทุกครั้งที่อ่าน มันอ่านทั้งภาพเท่ากันหมด ราคาเท่าเดิมเสมอ** ไม่มี "การมองแบบถูกๆ" ให้เลือกเลย (Perceiver ตัวแรกวนอ่านหลายรอบด้วยซ้ำ ส่วน IO ลดเหลือรอบเดียวเพราะเปิดทางให้ output query ดึงรายละเอียดตรงจาก input ได้)

### จริงๆ ทั้งสามอันคือความล้มเหลวแบบเดียวกัน

|               | ใครตัดสินว่าจะอ่านอะไร              | อ่านกี่ครั้ง | ราคาต่อครั้ง             |
| ------------- | ----------------------------------- | ------------ | ------------------------ |
| RAM 2014      | โมเดลเลือกตำแหน่ง / **คนเลือกสเกล** | หลายครั้ง    | คงที่                    |
| ViT 2020      | **คน** (patch size)                 | ครั้งเดียว   | คงที่                    |
| Perceiver IO  | **คน** ($M$)                        | ~ครั้งเดียว  | คงที่ (และแพงสุดในโมเดล) |
| **ที่ผมจะทำ** | **โมเดล ทั้ง $l$ และ $s$**          | หลายครั้ง    | **ผันแปรตาม $s$**        |

ทุกอันบนตารางนี้ **คนเป็นคนตัดสินใจเรื่องงบการอ่าน แล้วล็อกไว้ตั้งแต่ก่อนเห็นภาพ** ต่างกันแค่ล็อกไว้ที่ตัวแปรไหน

## Latent space ที่ visual transformer ยังไม่ได้ใช้

ในการทำ image classification ปัจจุบัน โมเดลใช้ visual data classify คำตอบได้ทันทีเลย โดยไม่ต้องรอ $z$ ก่อนหน้าคำนวณให้

เช่น ถามว่าในภาพมีหมาพันธุ์อะไร และแมวพันธุ์อะไร — **คำถามหมาไม่ได้ขึ้นกับคำถามแมวเลย** ทั้งคู่ทำขนานกันได้พร้อมกันใน $z$ เดียว

ด้วยสิ่งนี้มันสร้าง shortcut ขึ้นในโมเดล ที่การ predict จากภาพตรงๆ มันลด loss ได้เร็วกว่าการไป form latent thought

```
        ┌────────────── path B (shortcut) ──────┐
        │                                       ↓
[<s>] [v₁ ... v₅₇₆] [question] [z₁ ... z_k] [answer]
        │                        ↑   │          ↑
        └──── path A, hop 1 ─────┘   └──────────┘
                                     path A, hop 2
```

|                       | Route                    | Attention edges                                       |
| --------------------- | ------------------------ | ----------------------------------------------------- |
| **path A** (intended) | $v \to z \to \text{ans}$ | $z_i$ attends to $v_j$, **then** ans attends to $z_i$ |
| **path B** (shortcut) | $v \to \text{ans}$       | ans attends to $v_j$ **directly**                     |

|                         | path A                         | path B                                   |
| ----------------------- | ------------------------------ | ---------------------------------------- |
| Hops required           | **2**, across different layers | **1**                                    |
| State at initialisation | **random** — never trained     | **fully trained** — it _is_ the base VLM |
| Availability            | requires two learned edges     | **available at every one of 32 layers**  |

**optimizer เลือก path B ถูกแล้ว** ไม่ใช่ bug — 1 hop ที่เทรนมาแล้ว ชนะ 2 hop ที่เริ่มจาก random เป็นเรื่องปกติมาก และ $v_i$ ไม่ได้เป็น shortcut เส้นเดียว มันเป็น 32 เส้นพร้อมกัน (ทุก layer) — เลยเป็นเหตุผลว่าทำไม regularize ปิดไม่ไหว

> ⚠ ตารางข้างบนเป็นเคสของ **VLM ที่แปะ latent token เข้าไป** (LLaVA-style) ซึ่งมีของที่ pretrain มาแล้วเป็นตัวแปร
> ถ้าเทรน from scratch เอง path B ไม่ได้ "เทรนมาแล้ว" — แต่มันก็ยังชนะอยู่ดี เพราะมันคือ **feedforward map ที่ถูกที่สุดที่ตอบโจทย์ได้** GD หาเจอก่อนเสมอ
> คนละกลไก แต่ผลลัพธ์เดียวกัน เวลาพูดต้องแยกให้ออก ไม่งั้นโดนจับได้

**กฎรวมของมันคือ: อะไรที่เลี่ยงได้ จะถูกเลี่ยง** — latent, glimpse, CoT, layer, auxiliary head โดนหมด และมีทางแก้อยู่ 3 ทาง (supervise มันตรงๆ / ทำให้ path A ถูกลงแล้วลงโทษ path B / **ลบ path B ทิ้ง**) — **มีแค่ทางที่สามที่แข็งจริง** อีกสองทางเป็นการต่อรองกับ optimizer ซึ่งสุดท้ายมันชนะ

## ทำไมภาษาถึงไม่เจอปัญหานี้

ไม่ใช่เพราะภาษา "ลึกกว่า" นะ — เหตุผลจริงมี 2 ข้อ และมันเป็นเรื่องเชิงโครงสร้างล้วนๆ

**1. ภาษามันเป็น sequential โดยโครงสร้าง** — จะออก token ที่ $t+1$ พร้อมกับ token ที่ $t$ ไม่ได้ ต้องเห็นตัวก่อนหน้าก่อน ส่วนภาพอ่านทีเดียวหมดได้ ไม่มีอะไรบังคับให้เป็นลำดับ

พูดให้ตรงกว่านั้น: CoT ไม่ได้เพิ่มความสามารถทางสถาปัตยกรรมเลย มันแค่**เอา context window มาใช้เป็นเทปความจำภายนอก** แล้วเปลี่ยนวงจรความลึกคงที่ให้กลายเป็นเครื่องจักรวนซ้ำ (transformer ความลึกคงที่อยู่ใน TC⁰ — พอมี CoT ยาว poly(n) มันขึ้นไปเป็น P พอดี) **ลูปมันอยู่ข้างนอก stack ไม่ใช่ข้างใน**

**2. ข้อความในโลกมีขั้นตอนการคิดเขียนไว้ให้ฟรี** — มนุษย์เขียนวิธีทำเลขไว้ในเน็ตอยู่แล้ว next-token loss เลยได้ supervision รายขั้นมาฟรีๆ ส่วนภาพ **ไม่มีใครรู้ด้วยซ้ำว่า "ขั้นตอนการมองที่ถูกต้อง" หน้าตายังไง** (gaze trace? eye-tracking? ยังไม่มีใครนิยาม)

> ตัวอย่างที่ห้ามใช้: "ทำนายคำต่อไปของ 1 2 3 4 5" — อันนี้ **ไม่ลึก** มันเป็นงานทรง induction head ซึ่งเป็นวงจร 2 layer แก้ได้ตื้นๆ ถ้ายกอันนี้ให้อาจารย์ฟังโดนสวนแน่
> ตัวอย่างที่ควรใช้: **โจทย์เลขหลายขั้นแบบ GSM8K** — ขั้นที่ $t$ ต้องใช้ _ผลลัพธ์_ ของขั้นที่ $t-1$ ประมาณ 5 ขั้น และไม่มีทางลัด 1 hop เลย

$$\text{ภาษา} = \text{ยากแบบลึก (deep-hard)} \qquad \text{ภาพส่วนใหญ่} = \text{ยากแบบกว้าง (wide-hard)}$$

ยากแบบกว้าง = ของเยอะ ภาพใหญ่ ต้องดูหลายที่ — แต่ทุกที่ดูขนานกันได้ multi-head จัดการจบใน hop เดียว
ยากแบบลึก = ไม่รู้ว่าต้องดูตรงไหนต่อ จนกว่าจะดูตรงนี้เสร็จก่อน

## การ reframe ปัญหา

จากเดิม: **ต้อง optimize ยังไงให้มองภาพๆ หนึ่งเข้าใจ**

เป้าหมายใหม่: **"ต้อง optimize ยังไง ถ้า attention size เล็ก แต่โมเดลเลือกได้ว่าจะมองอะไรและจดอะไร"**

**นี่ไม่ใช่การเปลี่ยนวิธีแก้ปัญหา แต่เป็นการเปลี่ยนตัวปัญหา** — เป็นท่าที่ถูกต้องเวลาเจอ field ที่แออัด

ผลข้างเคียงที่ดี: พอตั้งกรอบแบบนี้ งานทุกอันที่คนอื่นทำมา **กลายเป็น special case ที่ `attention size = N`** แทนที่จะเป็นคู่แข่ง

ไอเดียหลักคือให้ latent คำนวณทั้ง $l$ (ตำแหน่ง) และ $s$ (สัดส่วนของภาพที่จะครอบ = ซูมเข้าออก)

> ⚠ ใช้ตัว $s$ อย่าใช้ $k$ — เพราะ $k$ มันชนกับ "จำนวนวงของ retina" ใน RAM และชนกับ "ความยาวโซ่" ในโจทย์ pointer-chase ทีหลัง

|                        | ตำแหน่ง  | **ความละเอียด / scale**                               |
| ---------------------- | -------- | ----------------------------------------------------- |
| RAM 2014               | เรียนรู้ | **คงที่** (3 scale ตายตัว)                            |
| STN 2015               | เรียนรู้ | เรียนได้ในทางทฤษฎี **แต่ไม่มีใครศึกษาจริงจัง**        |
| DRAW 2015              | เรียนรู้ | **เรียน $\sigma$ กับ stride ได้** ← ตัวเดียวที่ทำจริง |
| Deformable DETR 2021   | เรียนรู้ | **เลือกจากชั้นที่มีให้** (pyramid ตายตัว)             |
| ViT / ทุกอย่างปัจจุบัน | —        | **คงที่** (patch size ตายตัว)                         |

> ⚠ แถว Deformable DETR ต้องพูดให้ตรง — มันเรียน sampling offset ต่อ query **และ** เรียนน้ำหนักว่าจะหยิบจาก feature level ไหน คือมันไม่ได้ "คงที่" เป๊ะๆ
> ที่ตรงกว่าคือ: **เซ็ตของสเกลมันตายตัวและไม่ต่อเนื่อง โมเดลเลือกจากเมนู ไม่ได้ปล่อยค่าสเกลออกมาเอง**
> ถ้าพูดว่า "ไม่มีใครทำ scale เลย" อาจารย์ที่ตามสายนี้จะสวนทันที

ทำไมมันน่าสนใจกว่าแค่ "เพิ่ม parameter อีกตัว"?

$s_t$ **ไม่ใช่แค่พารามิเตอร์ มันคือการตัดสินใจเรื่องงบประมาณ**

- ซูมออก = สำรวจ (explore)
- ซูมเข้า = ยืนยัน (exploit)

โมเดลต้องเรียนรู้ว่า _"ตอนนี้ผมกำลังหา หรือกำลังตรวจสอบ"_ — **เป็นพฤติกรรมที่ตีความได้และวัดได้**

## ทำไมผมถึงเลือกทำอันนี้ก่อน

ส่วนนี้คือคำตอบว่า decision มันมาจากไหน มี 5 ข้อ เรียงจากหนักไปเบา

### 1. มันเป็นทางเดียวที่ "ลบ path B" ได้จริง ไม่ใช่แค่ลงโทษมัน

จาก §latent space ข้างบน — ทางแก้ที่แข็งจริงมีทางเดียวคือลบเส้นทางเลี่ยงทิ้ง

**ถ้า latent เป็นคนสั่งว่าจะอ่านตรงไหน คำตอบจะ attend ไปหา pixel ที่ไม่เคยถูกอ่านไม่ได้ เพราะมันไม่อยู่ใน sequence เลย** — path B ไม่ได้ถูกลงโทษ มันไม่มีอยู่ตั้งแต่แรก

นี่คือความต่างที่สำคัญที่สุดระหว่างไอเดียนี้กับงาน latent visual token ทั้งกอง: ของเขาแปะ $z$ เพิ่มเข้าไปข้างๆ $v$ แล้วหวังว่าโมเดลจะใช้ **ในขณะที่ $v$ ยังอยู่ครบ** ของเรา $v$ จะมีก็ต่อเมื่อ $z$ สั่งให้ไปเอามา

### 2. มันทำให้ latent มี "ข้อมูล" ไม่ใช่แค่ "การคำนวณ"

อันนี้คือเหตุผลเชิงทฤษฎีที่ผมคิดว่าแข็งที่สุด

latent ที่เป็นแค่ฟังก์ชันของสิ่งที่โมเดลรู้อยู่แล้ว มันมี $I(z_t ; y \mid \text{prefix}) = 0$ — **แปลว่ามันซื้อความลึกในการคำนวณได้ แต่ไม่เคยเพิ่มข้อมูลใหม่เลย** พฤติกรรมแบบ placeholder เลยเป็น**ค่า default ทางคณิตศาสตร์ ไม่ใช่อาการของการเทรนพัง** ซึ่งอธิบายได้เลยว่าทำไมงานที่ผ่านมามันวัดแล้วได้ $\alpha \approx 0, \beta \approx 0$

พอ latent เป็นคนตัดสินว่าจะอ่านอะไร:

$$\text{read} = \rho(x, l(z), s(z)) \quad\Longrightarrow\quad I(z ; y \mid \text{glance}) > 0$$

**ข้อมูลที่เข้ามาใหม่ขึ้นกับสิ่งที่ latent ตัดสินใจ** — มันเลยไม่ใช่ placeholder ได้อีกต่อไปในเชิงโครงสร้าง ไม่ต้องไปหวังพึ่ง loss

ของแถมที่มีค่ามาก: **จากเดิม latent เป็นเวกเตอร์ 4096 มิติที่ไม่มีใครตีความได้ กลายเป็นพิกัด 2 ตัวกับสเกล 1 ตัว ที่พล็อตทับบนภาพได้เลย** ปัญหา interpretability หายไปครึ่งนึงฟรีๆ

### 3. ช่องมันว่างจริง และว่างมานาน

DRAW ทำ learned scale ไว้ตั้งแต่ 2015 **แล้วไม่มีใครตามต่อ 10 ปี** — ในขณะที่ learned position มีคนตามเต็มไปหมด (STN, deformable, IPS, V\*, ZoomEye) นี่ไม่ใช่ช่องที่ว่างเพราะมันไม่สำคัญ มันว่างเพราะทุกคนไปโฟกัสที่ "ดูตรงไหน" จนลืม "ดูละเอียดแค่ไหน"

### 4. ผมไม่ได้ลงไปแข่งในตลาดที่อิ่มตัวแล้ว

อันนี้คือเหตุผลเชิงกลยุทธ์ — จากที่ไล่อ่าน landscape ของ ViT มา ทุกวิธีที่พยายามยัด spatial prior กลับเข้า ViT (conv stem, TNT, T2T, distillation, Swin RPB) **ได้กำไรพอๆ กันหมดประมาณ 1.5–2%** คือมันซื้อของชิ้นเดียวกันด้วยเงินคนละสกุล แปลว่าใครชนะขึ้นกับ**ต้นทุน ไม่ใช่ความฉลาด** — ตลาดนั้นอิ่มแล้ว

> ⚠ อันนี้เป็นข้อสังเกตของผมเองจากการอ่าน ไม่มี paper ไหน claim ไว้ตรงๆ และไม่มีทฤษฎีรองรับ — เวลาพูดต้องบอกว่าเป็น observation ไม่ใช่ result

ไอเดียนี้ไม่ได้อยู่ในตลาดนั้น เพราะผมไม่ได้แข่งว่าจะ encode ยังไงให้ดีขึ้น ผมเปลี่ยนว่า**จะอ่านอะไรเข้ามาตั้งแต่แรก**

และถ้าดูช่องว่างเทียบกับ compute ที่ต้องใช้ **"test-time compute สำหรับภาพ" คือช่องที่กว้างที่สุดตอนนี้** และใช้ compute ระดับกลางๆ ไม่ต้องมีคลัสเตอร์ — ซึ่งเป็นเรื่องเดียวกับที่ผมจะทำพอดี (จำนวนการอ่านผันแปรตาม input = test-time compute ชัดๆ)

### 5. "ทำไมต้องตอนนี้" — เพราะสาเหตุที่ RAM ตายมันหมดอายุแล้ว

**มันไม่ได้ตายเพราะ REINFORCE** อย่างที่คนชอบพูดกัน เหตุผลจริงเรียงตามน้ำหนัก:

1. **การอ่านทีละครั้งฆ่า parallelism บน GPU** — RAM ใช้ FLOPs น้อยกว่า 3 เท่า แต่ wall-clock ช้ากว่า ยุคนั้น FLOPs กำลังถูกลงทุกปี มันเลยประหยัดผิดของ
2. อ่านน้อยเกินไป (ทั้งภาพได้ข้อมูลมาประมาณพันมิติ)
3. $h_t$ เป็นคอขวดที่ไม่เคยถูกแก้
4. hardware lottery
5. **cluttered MNIST ไม่เคยบังคับให้ต้องคิดเป็นลำดับ** — RAM พิสูจน์แค่ว่า _การเลือกที่จะมอง_ มีประโยชน์ ไม่เคยพิสูจน์ว่า _การมองเป็นลำดับ_ มีประโยชน์

ข้อ 1 กับข้อ 5 คือข้อที่เปลี่ยนไปแล้วทั้งคู่ — ตอนนี้เราอยากได้ test-time compute กันอยู่แล้ว (ยอมช้าแลกกับคิดได้) และเราสร้างโจทย์ที่บังคับให้เป็นลำดับเองได้

ส่วนไอเดีย pointer เอง (**ทำนายที่อยู่ แล้วอ่านเฉพาะตรงนั้น**) ไม่เคยตายเลย มันไปโผล่ใน deformable attention, RAG, tool use, agent ที่รัน `grep` — กลไกตาย แต่ abstraction รอด

## กลไก

$$\text{latent } z_t \ \longrightarrow\ (l_t,\ s_t) \ \longrightarrow\ \rho(x, l_t, s_t) \ \longrightarrow\ z_{t+1}$$

| ตัวแปร                   | ความหมาย                      | ช่วงค่า                      |
| ------------------------ | ----------------------------- | ---------------------------- |
| $z_t \in \mathbb{R}^{d}$ | latent state ณ รอบที่ $t$     | —                            |
| $l_t \in [-1,1]^2$       | จุดศูนย์กลางที่จะมอง          | normalized coords            |
| $s_t \in (0, 1]$         | **สัดส่วนของภาพที่จะครอบ**    | 0.02 = ซูมสุด, 1.0 = ทั้งภาพ |
| $g$                      | ขนาด grid ที่อ่าน (**คงที่**) | 16×16                        |

$$l_t = \tanh(W_l z_t), \qquad \log s_t = W_s z_t \ \Rightarrow\ s_t = \mathrm{clip}\big(e^{W_s z_t},\ s_{\min},\ 1\big)$$

ทำนาย $\log s$ ไม่ใช่ $s$ ตรงๆ เพราะสเกลมันควรเป็น multiplicative (ซูม 2 เท่ากับซูม 4 เท่า ควรห่างกันเท่าๆ กับ 4 เท่ากับ 8 เท่า) และมันกัน gradient ระเบิดไปในตัว

grid ที่จะไปอ่าน — อันนี้คือ STN affine ที่ล็อกให้เหลือแค่ isotropic scale + translation:

$$p_{ij} = l_t + s_t \cdot (u_i,\ v_j), \qquad \rho[i,j] = \text{bilinear}\big(x,\ p_{ij}\big)$$

โดยที่ $(u_i, v_j)$ เป็น grid คงที่ $g \times g$ บน $[-1,1]^2$

differentiable ทั้งคู่:

$$\frac{\partial \rho}{\partial l_t} = \frac{\partial \rho}{\partial p} \qquad\qquad \frac{\partial \rho}{\partial s_t} = \sum_{ij}\frac{\partial \rho}{\partial p_{ij}}\cdot (u_i, v_j)$$

**gradient ของสเกลอ่านออกได้ตรงๆ เลย: มันคือ image gradient ถ่วงด้วยระยะจากจุดศูนย์กลาง** = _"ขอบนอกให้ข้อมูลเพิ่มมั้ย ถ้าไม่ ก็ซูมเข้า"_

> ทำไมมันถึง differentiable ได้ทั้งที่ RAM ทำไม่ได้: **gradient มันตายสองชั้น ไม่ใช่ชั้นเดียว**
> ชั้นที่ 1 = `crop` มันปัดลง pixel grid → $\partial \rho / \partial l = 0$ เกือบทุกที่ ← **อันนี้คือตัวฆ่าจริงของ RAM** และแก้ได้ด้วย interpolation (นี่คือสิ่งที่ STN ทำ)
> ชั้นที่ 2 = การ sample จาก distribution → อันนี้เป็นกำแพงจริงเฉพาะตอนที่ตัวเลือกมันไม่ต่อเนื่องจริงๆ ซึ่ง Gaussian มัน reparameterize ได้อยู่แล้ว
> คนชอบเหมารวมสองชั้นนี้เป็นอันเดียว แล้วสรุปผิดว่า "เลือกที่จะมอง = discrete = ต้องใช้ RL"

### ⚠ ส่วนที่ตัดสินว่าไอเดียนี้รอดหรือตาย: aliasing

**ถ้าไม่ทำอันนี้ ไอเดียจะพังแบบเงียบๆ**

ถ้า $s_t$ ใหญ่ (ครอบพื้นที่กว้าง) แต่ grid ยังเป็น $g \times g$ เท่าเดิม → **sampling rate ต่ำกว่า Nyquist → aliasing** → อ่านได้ค่าขยะ แล้ว gradient ก็ขยะตาม โมเดลจะเรียนจากสัญญาณที่ผิดโดยที่ loss ไม่ได้บอกอะไรเลย

ทางแก้: **อ่านจาก image pyramid (mipmap) แล้ว interpolate ข้าม level ด้วย**

$$\ell^* = \log_2\!\left(\frac{s_t \cdot W}{g}\right), \qquad \rho = (1-\alpha)\cdot\text{bilinear}\big(x^{(\lfloor \ell^*\rfloor)}, p\big) + \alpha\cdot\text{bilinear}\big(x^{(\lceil \ell^*\rceil)}, p\big)$$

นี่คือ **trilinear sampling** — เหมือนที่ deformable attention ทำข้าม feature map หลาย scale และเหมือนที่กราฟิกทำ mipmap มา 30 ปีแล้ว ไม่ใช่ของใหม่ แค่ไม่มีใครเอามาต่อกับ learned scale

### แต่ pyramid ไม่ใช่ implementation detail — มันคือพระเอกของเรื่อง

พอมี pyramid แล้ว trade-off มันกลายเป็น**ของจริงเชิงกายภาพ**:

$$s_t \text{ ใหญ่} = \text{เห็นกว้าง แต่เบลอจริงๆ} \qquad s_t \text{ เล็ก} = \text{เห็นคม แต่แคบ}$$

$$\Longrightarrow\ \textbf{โมเดลโกงด้วยการตั้ง } s_t = 1 \textbf{ ตลอดไม่ได้ เพราะมันจะเห็นแต่ภาพเบลอ}$$

**ถ้าไม่มี pyramid โมเดลจะเรียนรู้ที่จะซูมออกสุดแล้วจบ** — แล้วมันก็จะกลายเป็น ViT ที่แพงกว่าเดิม นี่คือ shortcut เฉพาะของไอเดียนี้ และมันเป็นตัวอย่างของกฎ "อะไรที่เลี่ยงได้ จะถูกเลี่ยง" ตรงๆ

พูดอีกแบบ: **pyramid คือการลบ path B ในระดับ physics** ไม่ใช่ระดับ loss — ซึ่งกลับไปตรงกับ §1 ของเหตุผลข้างบนพอดี

## จะรู้ได้ยังไงว่ามันเวิร์ค

| Metric                                                             | บอกอะไร                                              |
| ------------------------------------------------------------------ | ---------------------------------------------------- |
| $s_t$ เทียบกับ $t$                                                 | coarse-to-fine เกิดเองมั้ย                           |
| $\mathrm{Var}_t[l_t]$                                              | location collapse มั้ย (ไปจ้องที่เดิมทุกรอบ)         |
| IoU($l_T$, gt box)                                                 | grounding ถูกมั้ย                                    |
| **accuracy เทียบกับ read-fraction** $\dfrac{\sum_t (s_t W)^2}{HW}$ | **"ทำได้ 90% โดยอ่านแค่ 2%"** ← กราฟที่ไม่มีใครพล็อต |
| accuracy เทียบกับความยาวโซ่                                        | ลึกขึ้นแล้วยังรอดมั้ย                                |

**รูปที่ขายงานได้จริงคือรูปเดียว: พล็อต $s_t$ เทียบกับ $t$ แล้วเห็นเส้นลาดลง**

เพราะนั่นแปลว่า **coarse-to-fine เกิดขึ้นเอง ไม่ได้ถูกบังคับ** — โมเดลเรียนรู้ _กลยุทธ์_ ไม่ใช่แค่ fit และมันเชื่อมกับทฤษฎีที่มีอยู่แล้วด้วย: coarse-to-fine = **graduated non-convexity** ซึ่งเป็นวิธีมาตรฐานในการข้ามกำแพง optimization ที่เล่าไว้ตอนต้น → **โมเดลค้นพบวิธีแก้กำแพงด้วยตัวเอง**

### แต่การทดลองที่วัด contribution จริงๆ ไม่ใช่การเทียบกับ ViT

อันนี้ผมว่าสำคัญ อย่าไปเทียบ "โมเดลผม vs ViT" เพราะมันต่างกันสิบอย่างพร้อมกัน แปลผลไม่ได้

**contribution ของผมคือตัวแปรเดียว: $s$ เรียนได้หรือไม่ได้** เพราะฉะนั้นการทดลองหลักคือ:

| arm   | $l$      | $s$                     |
| ----- | -------- | ----------------------- |
| A     | เรียนรู้ | **คงที่** (เท่ากับ RAM) |
| B     | เรียนรู้ | **สุ่ม**                |
| **C** | เรียนรู้ | **เรียนรู้** ← ของผม    |
| D     | สุ่ม     | เรียนรู้                |

ทุก arm ใช้ **read budget เท่ากันเป๊ะ** จำนวน glimpse เท่ากัน grid เท่ากัน backbone เท่ากัน — เหลือตัวแปรเดียว
ถ้า C ไม่ชนะ A ที่งบเท่ากัน แปลว่า learned scale ไม่ได้ให้อะไร จบ

(arm D มีไว้เช็คว่าที่ชนะเป็นเพราะ scale จริง ไม่ใช่เพราะ position)

## ที่มันจะพัง

| ความเสี่ยง                | อาการ                             | ทางแก้                                               |
| ------------------------- | --------------------------------- | ---------------------------------------------------- |
| $s_t \to 1$ ตลอด          | ซูมออกสุด กลายเป็น ViT แพงๆ       | **pyramid** ทำให้เบลอจริง + budget loss $\sum s_t^2$ |
| $s_t \to s_{\min}$ ตลอด   | ซูมเข้าสุด หาไม่เจอ               | task loss ลงโทษเอง                                   |
| gradient ของ $s$ ระเบิด   | NaN / ค่ากระโดด                   | ทำนาย $\log s$ + clip                                |
| location collapse         | $\mathrm{Var}_t[l_t] \to 0$       | coverage loss / entropy bonus                        |
| coarse-to-fine ไม่เกิด    | เส้น $s_t$ แบน                    | อาจเพราะ $T$ น้อยไป **หรือโจทย์ไม่ต้องการมัน**       |
| **shortcut กลับมาเงียบๆ** | ดูเหมือนเวิร์ค แต่จริงๆ ไม่ได้คิด | ต้องเช็คโจทย์ทุกครั้ง (ดูหัวข้อถัดไป)                |

แถวสุดท้ายคืออันตรายที่สุด เพราะมันไม่แสดงอาการ — accuracy ขึ้น แต่โมเดลอาจจะแค่ทำ open-loop คือคำนวณจุดที่จะมองทั้งหมดตั้งแต่ glimpse แรกแล้วยิงขนานกัน ซึ่ง**ไม่ต้องคิดเป็นลำดับเลย** เทสง่ายๆ คือเทียบกับ arm ที่บังคับให้ขนาน ถ้าเท่ากัน = ไม่มี reasoning เกิดขึ้น

## ปัญหาที่ต้องแก้ก่อนทุกอย่าง: ไม่มีโจทย์

$$\textbf{vision ไม่มี GSM8K}$$

benchmark ภาพเกือบทั้งหมดสืบทอดมาจากยุค CNN คือ**ยากแบบกว้าง ไม่ใช่ยากแบบลึก** ซึ่งแปลว่า **ต่อให้โมเดลดีแค่ไหน ก็พิสูจน์อะไรไม่ได้เลย** เพราะโจทย์ไม่เคยต้องการการคิดเป็นลำดับตั้งแต่แรก

เช็คลิสต์ว่าโจทย์บังคับให้ลึกจริงมั้ย มี 4 ข้อ ต้องผ่านครบ:

1. **มีโซ่การอ้างอิง** — ต้องรู้ผลของขั้นก่อนถึงจะรู้ว่าไปไหนต่อ
2. **มีช่องว่างเรื่องความละเอียด** — ดูภาพย่อแล้วตอบไม่ได้
3. **blind baseline ต่ำ** — ลบภาพทิ้งแล้วตอบไม่ได้ (กัน language prior)
4. **อัตราส่วนพื้นที่สูง** — ของที่สนใจเล็กกว่าเฟรมมากๆ

# ไอเดียรอง retina แบบ associative retrieval (เชื่อม Hopfield)

## จริงๆ มันคืออันเดียวกันกับข้างบน

แยกออกมาเป็นสองหัวข้อเพราะมันตอบคนละคำถาม แต่มันคือลูปเดียวกัน:

$$\underbrace{(l, s) \text{ predictor}}_{\textbf{มือ} \ -\ \text{"มองยังไง"}} \qquad\qquad \underbrace{\text{associative retrieval}}_{\textbf{สมอง} \ -\ \text{"มองที่ไหนต่อ"}}$$

ข้างบนบอกว่า _เมื่อรู้แล้วว่าจะมองไหน จะอ่านออกมายังไงให้ differentiable และโกงไม่ได้_
อันนี้ตอบว่า _แล้วจะรู้ได้ยังไงว่าควรมองตรงไหนต่อ_ — โดยไม่ต้องเดินฝ่ากำแพง และไม่ต้องใช้ RL

เฟส 1 ใช้ MLP ธรรมดายิง $(l,s)$ ออกมาก่อนก็ได้ แล้วค่อยเปลี่ยนเป็นอันนี้ในเฟส 1.5

## สูตร

$$\text{glance ความละเอียดต่ำ} \ \longrightarrow\ M = \{m_p\}_{p=1}^{N_{low}} \quad \text{(associative memory)}$$
$$\text{latent } z_t \ \longrightarrow\ q_t = W_q z_t \quad \text{(query)}$$
$$l_t = \sum_{p} \mathrm{softmax}\big(\beta \langle q_t, m_p\rangle\big)_p \cdot \mathrm{pos}(p)$$

**นี่คือ modern Hopfield retrieval เป๊ะๆ แต่ retrieve "ที่อยู่" แทน "เนื้อหา"**

$$\text{Hopfield ปกติ:}\quad \xi^{new} = X\,\mathrm{softmax}(\beta X^\top \xi) \qquad \text{— ดึงเนื้อหากลับมา}$$
$$\text{อันนี้:}\quad l = P\,\mathrm{softmax}(\beta M^\top q) \qquad\qquad \text{— ดึง \textbf{พิกัด} กลับมา แล้วค่อยไปอ่านของจริงที่ความละเอียดเต็ม}$$

## ทำไมมันสวย

| ปัญหา                 | แก้ได้ยังไง                                                   |
| --------------------- | ------------------------------------------------------------- |
| กำแพง / local minimum | **ไม่มีการเดิน — retrieve ตรงๆ** (ไม่ต้องไต่ gradient บน $l$) |
| ต้องใช้ RL มั้ย       | **ไม่ — softmax differentiable**                              |
| ราคา                  | $O(N_{low})$ บนภาพย่อ **ถูกมาก** (ย่อ 8 เท่า = ถูกลง 64 เท่า) |
| ตีความได้มั้ย         | **ได้ — attention map บนภาพย่อ = "มันกำลังนึกถึงอะไร"**       |

$$\boxed{\ \text{"คิดในหัว"} = \text{query เข้า associative memory ที่สร้างจาก glance}\ }$$

และมันแก้ปัญหาที่เล่าไว้ตั้งแต่หัวข้อแรกพอดี — เรื่องที่ว่า "จะเลื่อนจากตาข้างขวาไปตาข้างซ้ายได้ยังไง ถ้าไม่รู้ว่ามีอยู่" คำตอบคือ **ภาพย่อรู้ว่ามีอยู่ แค่ไม่รู้รายละเอียด** เลย retrieve พิกัดจากภาพย่อ แล้วไปอ่านรายละเอียดที่ความละเอียดเต็มทีหลัง

**นี่คือเรื่องเล่าที่รวมทุกอย่างที่เคยอ่านมา** — Hopfield (retrieval) + Perceiver (latent) + RAM (glimpse) ไม่ใช่การเริ่มใหม่ แต่คือการรวมร่าง

ประโยคที่สรุปมันได้ดีที่สุด: **RAM คือ Hopfield ที่ตัวเอเจนต์เลือก probe ตัวถัดไปเองได้**

## ข้อควรระวัง

- **softmax แบบนี้เป็น soft** → ถ้า attention กระจาย $l_t$ จะไปตกตรงกลางระหว่างจุด (centroid problem) ซึ่งอาจจะไม่มีอะไรอยู่ตรงนั้นเลย → ต้องใช้ $\beta$ สูง หรือ top-1 + straight-through
- **ไม่ควร retrieve ตำแหน่งเดียว** ควร retrieve $K$ ตำแหน่ง (แบบ deformable) แล้วอ่านพร้อมกัน → รักษา parallelism ไว้ ซึ่งคือเหตุผลที่ RAM ตายพอดี
- $\beta$ ที่สูงเกินไปทำให้ gradient ตาย ($\nabla\text{softmax} = \beta(\text{diag}(a) - aa^\top) \to 0$) — มี trade-off ตรงนี้อยู่ ต้องลองจริง
